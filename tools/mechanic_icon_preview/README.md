# #129 机制图标试玩

运行 `godot --path . tools/mechanic_icon_preview/mechanic_icon_preview.tscn`。

- 默认“爆破收益三卡”：先通过正式核心/引信技能满足前置，再提供爆破补分、爆破节拍、爆后留白；读卡前按H收起工具，选卡确认后核对构筑刷新。
- “爆破收益构筑”：爆破补分Lv.2、爆破节拍Lv.3、爆后留白Lv.1，与原有核心、五连补分加号及色彩聚焦回退并排。未发生触发行动，留白仍是常驻能力等级，不显示临时补棋剩余次数。
- “五连额外分”：连珠补分、五枚正好、长连收获三张合法候选；检查共用加号和完整触发条件，再选卡确认。
- “收益与倍率构筑”：额外分三卡分别Lv.1/Lv.2/Lv.3，与倍率Lv.1并排，检查加号/乘号、角色、等级及色彩聚焦文字回退。
- “布雷与传递”：通过正式入口先取得核心/引信，再提供两张合法常驻卡；选取并确认后检查构筑角色和等级。
- “传递接力”：已取得引信传递，单张接力卡仍须确认，正文保留总上限与每源1枚的区别。
- “引信构筑”：布雷/传递各Lv.1、接力Lv.2，以及原有核心和色彩聚焦文字回退；三张引信卡共用图元，以角色小字区分。
- “染色接续”：单张合法接续卡仍需确认，选取后检查构筑中的Echo/接续与Lv.1。
- “染色强化”：先取得接续，再提供染色扩散/再续一线两张合法卡，检查正文限制与选取后Spread/扩散或Chain/再续标签。
- “染色构筑”：三张染色常驻与未登记的色彩聚焦同时显示；共用水滴图元但角色不同，均显示等级，不显示消耗次数。
- “供给与倍率”：留白一手、加速播种、计分倍率。供给分别用−/+，倍率用×，保留完整规则与变化预览。可选卡确认，查看正式构筑刷新。
- “供给构筑”：同时装有两种临时供给、倍率与未登记的色彩聚焦。供给显示剩余3次，倍率显示Lv.1；两种供给同时生效相抵，但各自次数独立消耗。正常移动并触发实际补棋，检查3→2→1→消失；成功五连免补棋不扣次数。
- 原有“登场三卡”“强化三卡”“构筑与回退”继续保留。行扫横向、列扫纵向；同族用登场/补给/范围及等级区分，回退样例改为色彩聚焦。
- 支持中文/English、明亮/深色、普通/低特效；H隐藏或显示工具按钮。工具按钮采用两列和不透明底板，并置于HUD/弹窗上方；读卡和实际操作前按H收起，避免测试工具遮挡。
- “查看技能池”核对同一图元；“查看棋盘”暂收选卡后查看构筑，再返回选择。

入口使用真实Game、SkillRules和奖励命令。固定种子129，供给样例从第4次奖励起以满足中期候选条件；只提供本片代表候选，不代表自然掉落或平衡验收。不保存玩家设置、不记录回放、不收集真人数据。

追加 `-- --capture-icons` 可导出两语言×两主题×两尺寸×候选/构筑，共16组合，另留1张1024×640工具栏检查图，至 `.godot/issue129-blast-payoff-icons/captures/`。

Windows本机验证时，原隔离用户目录曾出现GLES初始化错误及白棋盘。改用工程内短目录后捕获和再次启动正常。可在当前启动终端临时设置（仅影响该终端及子进程，不改系统设置）：

```powershell
$env:APPDATA = Join-Path $PWD '.godot/icon_user'
$env:LOCALAPPDATA = $env:APPDATA
New-Item -ItemType Directory -Force $env:APPDATA | Out-Null
godot --path . tools/mechanic_icon_preview/mechanic_icon_preview.tscn
```

这只是本机可复现的隔离办法，尚未证明引擎根因；原诊断保留在 evidence，遇到渲染异常不能据规则测试宣称可视验收通过。
