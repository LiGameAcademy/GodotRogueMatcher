# #130 连携节奏最小验收

运行 `res://tools/chain_rhythm_acceptance/chain_rhythm_acceptance.tscn`。静态场景实例化真实Game，无额外测试面板遮挡棋盘。禁用偏好持久化、记录和遥测；固定盘面不是自然抽选或平衡样本。

- 主键盘1：重载爆破→扫线。2：重载扫线→爆破。Enter：重载并执行当前例。标题显示当前案例。
- 也可手动执行：爆破例将(5,5)移动到(5,4)；反向例双击(1,4)行扫手。坐标从0开始，左右为x、上下为y。
- F1设置切低特效，F8快速；普通、快速、低特效、组合分别重播。现有暂停/略过/重试入口保留；按1/2或重试会通过Board取消旧演出并安装新固定例。

## 真人走查

1. 爆破→扫线：能否指出匹配落点、爆破中心(5,4)，以及被移除行扫手在(6,4)发出的横扫；是否清楚先后、真实命中和61分归拢。
2. 扫线→爆破：能否指出(1,4)横扫先触发、再由(5,4)爆破；与上一条方向相反，结果16分。检查来源已离场时是否容易误认。
3. 观察恢复操作是否及时，装饰/声音尾迹是否遮挡下一步；不要只因更快或更多特效判为更好。
4. 四种模式分别比较；普通模式在第一爆破时暂停/恢复，再中途重载另一例，确认没有后代抢跑或旧尾迹污染新盘。其余中断组合仍须单独记录。
5. 将“来源可辨/等待可接受/声音清楚”按例和模式填写真实观察；未知保持空。当前工具不直接收集真人数据，也不自动把技术有效升级为真人通过。

`-- --capture-rhythm` 在真实渲染下采集8例到 `.godot/issue130-chain-rhythm/real_capture.json` 后退出；技术失败或写盘失败退出非0，JSON的technical_valid只表示技术检查。Windows使用短临时APPDATA/LOCALAPPDATA（如`%TEMP%/rogue-chain130-play`），避免深工作树缓存路径问题。

墙钟统计从正式命令开始到恢复输入，事件时间是信号派发时刻；不是首像素/声卡延迟或GPU帧时间。headless报告带headless=true，不能当手感数据。本片未调整生产时长、声音、规则或强度，FJ05长链/异形及#131完整验收仍未完成。
