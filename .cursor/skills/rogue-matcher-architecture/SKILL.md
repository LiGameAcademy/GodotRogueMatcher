# 坚果连珠架构工作流

本技能只作为当前 Godot 工程的项目 skill 使用，不安装到全局。Cursor 工作区是引擎工程 `godot-rogue-matcher/`；GDC 与教程在上级目录。先遵循[通用Godot工程技能](../../../../GDC/agent-guidance/godot-engineering/SKILL.md)与[项目Agent规则](../../../../GDC/agent-rules/architecture.md)，再按任务读取[27 工程规范](../../../../GDC/27-目录命名与设计模式规范.md)的相关章节；本文补充本项目特有工作流。

来源：上级仓库 `../.agents/skills/rogue-matcher-architecture/SKILL.md`。Claude Code 镜像见 `.claude/skills/rogue-matcher-architecture/SKILL.md`。

## 获取当前契约

检查实际project.godot、相关场景/脚本、配置和祖先AGENTS.md。项目版本以当前工程与实际执行工具为准，不能根据历史文档认定框架已坏或已可用。

按需要读[09 架构](../../../../GDC/09-技术架构设计.md)的所有权与阶段流程，以及本任务对应GDC玩法文件。区分作者决策、提案和原型实现；特别不要从架构示例推导爆炸计分、阶段胜败或新技能的正式规则。

在本次任务内选用下述模式，多个模式相关时组合使用。缺少的信息若能从代码或现行设计确认，直接确认；只有影响正确性的未决语义才向作者询问，继续其他不依赖答案的工作。

## 新建模块或架构审查

- 先列模块唯一职责、权威状态拥有者、输入/输出和依赖方向；再决定目录与类，不从模式清单倒推空类。
- 按27功能目录归位，可复用场景与同名脚本并置。列出实际需要的文件，标明复用、迁出和新增；不把目录树全建一遍。
- 指明当前变化由哪种扩展点承接：组合Effect、选择策略、命令、阶段状态或外围Adapter。不需要模式的纯函数/数据类直接实现。
- 审查重点是第二份占格/总分、节点查找、动画决定规则、共享配置被修改、控制器中技能ID分支、无职责抽象及超限文件。只对本次范围给出整改与验证证据。

## 新增或组合Effect

- 明确触发时机、来源/目标、规则输入、合法空结果、次数/充能归属和计分来源。定义Resource只读，运行计数归实例。
- 复用现有叶子Effect与目标选择器；只有新行为确实不同才增加具体实现。叶子输出规则请求/结果，Resolver经棋盘/计分统一入口应用。
- 多效果时才创建Composite，与叶子保持同一契约；在实现前写明子效果执行顺序、每步目标重选或固定快照、已离场目标、后续触发事件入队时机与根行动预算。
- 读取27第4节的当前执行方案，不把“先应用叶子再执行下一叶子”误写成“先统一收集所有叶子请求”。改变组合执行语义时同时更新规则版本、设计和相关验证案例。
- 根据涉及的行为选验证案例：次序改变结果、首叶移除目标、合法空目标、离场快照、重复移除去重、预算超限、A/B实例计数隔离。单叶子变化不机械补全所有案例。

## 渐进迁移

- 根据实际引用与27迁移映射确定一个可交付职责，记录旧写入口、目标入口、场景依赖和相关教程；保留无关编辑器调参。
- 通过Godot编辑器移动资源时核对UID与引用；不可用时按项目现有路径/UID方式谨慎修改引用并检查，不删除UID重新生成。
- 新状态接管后停止旧入口写入，再删已移交实现；没有需要就不并存第二个长期主流程或复制框架代码。
- 验证改动涉及的解析、场景加载/实例化、路径、信号、无UI规则及重试清理。若没有可用编辑器/运行环境，保存改动并如实报告限制，不宣称已通过运行验收。

## 交付

交付文件与职责映射、当前契约和实际验证结果。代码变化同步对应可运行教程示例；目录/契约变化同步27或09，基础Agent规则改变时同步规则正文，工作流变化才修改本技能。

只有设计或审查请求时交付设计/发现，不自动开始游戏实现；只有局部实现请求时不顺带兑现整个架构目录、发布框架或修改未决玩法。用户后续明确授权的范围优先于文档中的旧提案。
