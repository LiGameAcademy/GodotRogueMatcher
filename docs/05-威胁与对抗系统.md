# 威胁与对抗系统 (Threats & Counter System)

---

## 一、设计理念 (Design Philosophy)

**核心理念：** 没有移动的怪物，只有系统故障。

游戏中的威胁不是主动攻击的敌人，而是系统本身的故障和逐渐增加的难度。玩家需要对抗的是"熵增"——系统逐渐变得混乱和不可控。

---

## 二、安全等级系统 (Security Level System)

### 1. 安全等级机制

#### 1.1 等级提升规则
- **提升间隔：** 每过 15 回合，安全等级 +1
- **显示位置：** 屏幕上方
- **显示格式：** `TRACE: [||||||....]` 或 `SECURITY LEVEL: 3`
- **初始等级：** Lv.1

#### 1.2 等级效果

**Lv.1（初始）：**
- 每回合生成 3 个球
- 无额外威胁

**Lv.2：**
- 每回合生成 3 个球
- 5% 几率生成"死像素"（Dead Pixel）

**Lv.3：**
- 每回合生成 4 个球
- 5% 几率生成"死像素"
- 10% 几率生成"粘滞扇区"（Sticky Sector）

**Lv.4+（极速死亡模式）：**
- 每回合生成 5 个球
- 10% 几率生成"死像素"
- 15% 几率生成"粘滞扇区"
- 5% 几率生成"数据风暴"（一次性生成 3 个球）

### 2. 安全等级显示

#### 2.1 视觉反馈
- **进度条：** 显示当前回合数 / 15（下一级所需回合）
- **颜色变化：** 
  - Lv.1-2：绿色
  - Lv.3：黄色
  - Lv.4+：红色
- **警告效果：** Lv.4+ 时屏幕边缘闪烁红色

#### 2.2 音效反馈
- **等级提升：** 播放警报音效
- **高等级：** 持续低沉的蜂鸣声

## 三、地形灾害 (Glitches)

### 1. 死像素 (Dead Pixel)

#### 1.1 特性
- **外观：** 黑色/灰色像素点，带有"损坏"标记
- **占用空间：** 1 格
- **阻挡效果：** 阻挡球的移动路径
- **不可移动：** 无法通过移动消除
- **不可消除：** 无法通过连线消除

#### 1.2 生成规则
- **生成概率：** 根据安全等级（Lv.2: 5%, Lv.4+: 10%）
- **生成位置：** 随机空位
- **生成限制：** 同时最多存在 3 个

#### 1.3 清除方式
- **方式1：** 使用炸弹炸掉
  - 炸弹 3x3 范围内可以清除死像素
- **方式2：** 冲击波震碎
  - 需要 2 次冲击波命中
  - 第一次：标记为"受损"（外观变化）
  - 第二次：完全清除
- **方式3：** 特殊消耗品（未来）
  - 如"修复工具"等

#### 1.4 策略影响
- **空间压力：** 占用宝贵空间
- **路径阻塞：** 阻碍球的移动
- **优先级：** 高优先级清除目标

---

### 2. 粘滞扇区 (Sticky Sector)

#### 2.1 特性
- **外观：** 半透明紫色区域，带有"粘滞"标记
- **占用空间：** 1 格（但不阻挡）
- **效果：** 球移动到此格后，定身 1 回合
- **持续时间：** 永久（直到被清除）

#### 2.2 生成规则
- **生成概率：** Lv.3: 10%, Lv.4+: 15%
- **生成位置：** 随机空位
- **生成限制：** 同时最多存在 2 个

#### 2.3 效果机制
```gdscript
func on_ball_enters_sticky_sector(ball: ChessPiece, sector: StickySector):
    # 球进入粘滞扇区
    ball.set_stuck(true)
    ball.stuck_turns = 1
    
func on_turn_end():
    # 回合结束时检查
    for ball in stuck_balls:
        ball.stuck_turns -= 1
        if ball.stuck_turns <= 0:
            ball.set_stuck(false)
```

#### 2.4 清除方式
- **方式1：** 使用炸弹清除
- **方式2：** 冲击波清除（1 次即可）
- **方式3：** 特殊消耗品

#### 2.5 策略影响
- **移动限制：** 限制球的移动路径
- **回合消耗：** 增加回合消耗
- **优先级：** 中等优先级清除目标

---

### 3. 数据风暴 (Data Storm) - 未来扩展

#### 3.1 特性
- **触发条件：** Lv.4+ 时，5% 概率触发
- **效果：** 一次性生成 3 个球（额外生成）
- **视觉：** 屏幕闪烁，粒子效果

#### 3.2 应对策略
- **提前准备：** 预留空间
- **快速消除：** 尽快消除以腾出空间

---

## 四、威胁生成系统 (Threat Spawning System)

### 1. 生成时机
- **回合结束：** 每回合结束时生成
- **安全等级提升：** 等级提升时可能生成额外威胁

### 2. 生成逻辑
```gdscript
func spawn_threats():
    var security_level = get_security_level()
    var threat_count = 0
    
    # 生成球
    spawn_balls(get_ball_count_for_level(security_level))
    
    # 生成死像素
    if randf() < get_dead_pixel_chance(security_level):
        spawn_dead_pixel()
        threat_count += 1
    
    # 生成粘滞扇区
    if security_level >= 3 and randf() < get_sticky_sector_chance(security_level):
        spawn_sticky_sector()
        threat_count += 1
    
    # 数据风暴
    if security_level >= 4 and randf() < 0.05:
        spawn_data_storm()
```

### 3. 生成位置
- **随机空位：** 优先选择空位
- **避开建筑：** 不生成在建筑上
- **分布均匀：** 避免集中生成

## 五、对抗策略 (Counter Strategies)

### 1. 预防策略

#### 1.1 空间管理
- **预留空间：** 保持足够的空位
- **及时清除：** 尽快消除以腾出空间
- **优化布局：** 合理规划建筑位置

#### 1.2 建筑选择
- **选择高效建筑：** 优先选择空间效率高的建筑
- **避免过度建设：** 不要建造过多建筑

### 2. 应对策略

#### 2.1 死像素应对
- **优先清除：** 使用炸弹或冲击波清除
- **路径规划：** 避开死像素规划路径
- **预留炸弹：** 保持至少 1 个炸弹备用

#### 2.2 粘滞扇区应对
- **避开路径：** 规划路径避开粘滞扇区
- **快速清除：** 使用炸弹或冲击波清除
- **利用效果：** 在某些情况下可以利用定身效果

### 3. 升级策略

#### 3.1 安全等级管理
- **快速通关：** 尽快达到目标分数，避免等级过高
- **效率提升：** 提高消除效率，减少回合数

#### 3.2 资源管理
- **金币储备：** 保持足够的金币购买应对物品
- **物品储备：** 保持炸弹等应对物品

## 六、威胁平衡 (Threat Balance)

### 1. 难度曲线
- **早期：** 威胁较少，玩家可以适应
- **中期：** 威胁逐渐增加，需要策略应对
- **后期：** 威胁密集，考验玩家极限

### 2. 平衡调整
- **生成概率：** 根据测试数据调整
- **威胁强度：** 确保有应对方法
- **玩家反馈：** 收集玩家反馈调整

### 1. 威胁视觉
- **死像素：** 黑色/灰色，带有"损坏"标记
- **粘滞扇区：** 半透明紫色，带有"粘滞"标记

### 2. 威胁音效

- **粘滞扇区生成：** 轻微的"粘滞"音效
- **安全等级提升：** 警报音效
- **高等级：** 持续低沉的蜂鸣声

## 八、未来扩展 (Future Extensions)

### 1. 新威胁类型
- **病毒：** 感染周围的球，改变颜色
- **防火墙：** 阻挡特定方向的移动
- **数据泄露：** 随机清除一个建筑

### 2. 威胁组合
- **组合效果：** 多个威胁组合产生额外效果
- **连锁威胁：** 一个威胁触发另一个威胁

### 3. 威胁升级
- **威胁等级：** 威胁本身也有等级，效果更强
