# 棋盘系统设计 (Grid System Design)

---

## 一、棋盘规格 (Grid Specifications)

### 1. 物理尺寸
- **网格大小：** 9x9 网格（共 81 格）
- **单元格大小：** 64x64 像素
- **网格间距：** 1 像素（可配置）
- **总尺寸：** 约 576x576 像素（不含间距）

### 2. 初始可用区域
- **中心区域：** 7x7 区域（共 49 格）
- **边缘区域：** 初始为"基岩/坏道"（不可用，共 32 格）
- **解锁方式：** 使用"钻头"道具解锁边缘格子

### 3. 区域类型

#### 3.1 可用区域 (Available)
- **状态：** 可以放置球、建筑、道具
- **视觉：** 正常网格显示
- **交互：** 可点击、可拖拽放置

#### 3.2 坏道区域 (Bad Sector)
- **状态：** 初始不可用，需要解锁
- **视觉：** 灰色/暗色显示，带有"损坏"标记
- **解锁：** 使用"钻头"道具解锁
- **解锁后：** 变为可用区域，永久解锁

#### 3.3 阻挡区域 (Blocked)
- **状态：** 被建筑、死像素等阻挡
- **视觉：** 显示阻挡物
- **交互：** 不可放置球，但可以放置某些建筑（如金矿）

## 二、实体层级系统 (Layer System)

为了逻辑清晰，Godot 中建议分层处理：

### 1. Layer 0 - 地基层 (Ground Layer)
- **Z-Index：** 0
- **内容：**
  - 地板网格
  - 被锁住的坏道
  - 购买的空地标记
- **渲染顺序：** 最先渲染
- **碰撞检测：** 不参与碰撞

### 2. Layer 1 - 设施层 (Facility Layer)
- **Z-Index：** 1
- **内容：**
  - 玩家建造的建筑
  - 遗物
  - 陷阱
- **特性：** 具有阻挡体积（阻挡球的移动）
- **碰撞检测：** 参与碰撞检测（阻挡 Layer 2）

### 3. Layer 2 - 数据层 (Data Layer)
- **Z-Index：** 2
- **内容：**
  - 球（数据包）
  - 宝箱（加密数据包）
  - 黑市终端
  - 死像素（Dead Pixel）
  - 粘滞扇区（Sticky Sector）
- **特性：** 可以移动或被消除
- **碰撞检测：** 参与碰撞检测（被 Layer 1 阻挡）

### 4. Layer 3 - 特效层 (Effect Layer)
- **Z-Index：** 3
- **内容：**
  - 爆炸特效
  - 浮动文字
  - 光标高亮
  - 路径显示
  - 粒子效果
- **特性：** 纯视觉效果，不参与逻辑
- **渲染顺序：** 最后渲染

## 三、空间管理 (Space Management)

### 1. 空间占用规则
- **设计原则：** 万物皆实体，一切皆占地
- **占用规则：**
  - 每个建筑占用 1 格
  - 每个球占用 1 格
  - 每个宝箱占用 1 格
  - 死像素占用 1 格
  - 特殊：幽灵球不占空间（可重叠）

### 2. 空间计算
- **可用空间 = 总格子数 - 占用格子数**
- **占用格子 = 建筑数 + 球数 + 宝箱数 + 死像素数 + 其他阻挡物**
- **剩余空间显示：** 屏幕上方显示剩余空位数

### 3. 空间不足处理
- **警告阈值：** 剩余空位 < 10
- **警告效果：** 屏幕边缘闪烁红色
- **危险阈值：** 剩余空位 < 3
- **危险效果：** 屏幕边缘持续闪烁，音效警告
- **失败条件：** 剩余空位 = 0 且无法生成新球

## 四、寻路系统 (Pathfinding System)

### 1. A* 寻路算法
- **实现：** 使用 Godot 的 `AStarGrid2D` 类
- **网格大小：** 9x9
- **移动模式：** 禁用对角线移动（`DIAGONAL_MODE_NEVER`）
- **障碍物：** 实时更新（建筑、死像素等阻挡物）

### 2. 路径计算
- **起点：** 选中棋子的当前位置
- **终点：** 玩家点击的目标位置
- **路径返回：** 坐标点数组（Vector2i 数组）
- **无路径处理：** 返回空数组，操作无效

### 3. 路径显示
- **显示时机：** 计算路径后立即显示
- **显示方式：** 高亮路径上的所有格子
- **显示颜色：** 蓝色/青色高亮
- **隐藏时机：** 移动完成后或取消操作

## 四、坐标系统 (Coordinate System)

### 1. 坐标定义
- **坐标系：** 二维整数坐标 (x, y)
- **原点：** 左上角为 (0, 0)
- **X 轴：** 从左到右递增
- **Y 轴：** 从上到下递增
- **范围：** x ∈ [0, 8], y ∈ [0, 8]

### 2. 坐标转换
- **世界坐标 → 网格坐标：**
  ```gdscript
  var grid_pos = Vector2i(
      floor(world_pos.x / (cell_size.x + grid_gap.x)),
      floor(world_pos.y / (cell_size.y + grid_gap.y))
  )
  ```
- **网格坐标 → 世界坐标：**
  ```gdscript
  var world_pos = Vector2(
      grid_pos.x * (cell_size.x + grid_gap.x),
      grid_pos.y * (cell_size.y + grid_gap.y)
  )
  ```

### 3. 坐标验证
- **边界检查：** 确保坐标在 [0, 8] 范围内
- **可用性检查：** 检查目标位置是否可用
- **阻挡检查：** 检查目标位置是否被阻挡

## 五、数据结构 (Data Structure)

### 1. 棋盘状态存储
```gdscript
# 使用 Dictionary 存储棋盘状态
var grid_data: Dictionary = {}  # {Vector2i: EntityData}

# EntityData 结构
class EntityData:
    var layer: int  # 0, 1, 2, 3
    var entity_type: String  # "BALL", "BUILDING", "LOOT_BOX", etc.
    var entity_ref: Node  # 实体节点引用
    var is_blocking: bool  # 是否阻挡
```

### 2. 快速查询
- **按坐标查询：** `grid_data.get(Vector2i(x, y))`
- **按类型查询：** 遍历 Dictionary，筛选 entity_type
- **按层级查询：** 遍历 Dictionary，筛选 layer

## 六、性能优化 (Performance Optimization)

### 1. 渲染优化
- **使用 CanvasLayer：** 分离 UI 和游戏世界
- **使用 YSort：** 自动管理 Z-Index（可选）
- **对象池：** 复用频繁创建/销毁的实体

### 2. 计算优化
- **批量处理：** 消除检测批量进行，避免每帧检测
- **缓存路径：** 缓存常用路径计算结果
- **延迟更新：** 非关键更新延迟到下一帧

### 3. 内存优化
- **对象池管理：** 球、特效等使用对象池
- **资源复用：** 共享材质和纹理
- **及时释放：** 不再使用的实体及时释放

## 七、扩展性考虑 (Extensibility)

### 1. 棋盘大小扩展
- **当前：** 9x9（固定）
- **未来：** 可配置棋盘大小（7x7, 9x9, 11x11 等）
- **实现：** 使用配置参数，动态生成网格

### 2. 特殊格子类型
- **当前：** 普通格子、坏道
- **未来：** 特殊效果格子（如双倍得分、传送门等）
- **实现：** 扩展 EntityData，添加格子类型字段

### 3. 多层棋盘（未来）
- **概念：** 多个 9x9 棋盘叠加
- **实现：** 扩展 Layer 系统，添加"棋盘层"概念
