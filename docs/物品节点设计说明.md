# 物品节点设计说明 (Item Node Design)

---

## 一、设计理念

采用**统一节点设计**和**策略模式（Strategy Pattern）**：

- **统一节点：** 道具和棋子使用同一个 `ChessPiece` 节点
- **道具即特殊棋子：** 道具被视为一类特殊的棋子，复用所有逻辑
- **策略对象：** `ItemData` 作为配置数据，定义道具的外观
- **无需特殊处理：** 不需要区分道具和棋子，统一处理

---

## 二、架构设计

### 1. 核心组件

```
ChessPiece (Node2D)
├── DisplayMode (枚举)
│   ├── SHAPE - 显示形状（普通棋子）
│   └── ICON - 显示图标（道具）
├── ItemData (Resource) - 策略对象（仅用于道具）
│   ├── id: String
│   ├── icon: Texture2D
│   ├── rarity: String
│   └── type: String
├── Polygon2D - 显示形状（棋子模式）
├── Sprite2D - 显示图标（道具模式）
└── GPUParticles2D - 辉光效果
```

### 2. 工作流程

```
ItemData (配置) → ItemPlacer.create_item() → Item (节点) → 放置到 Cell
```

---

## 三、实现细节

### 1. Item 节点 (`prefabs/item.gd`)

**职责：**
- 根据 `ItemData` 渲染图标
- 处理选择/取消选择动画
- 处理出现/移除动画
- 管理辉光粒子效果

**关键方法：**
```gdscript
func initialize(data: ItemData) -> void  # 初始化物品
func update_visual() -> void              # 更新视觉效果
func spawn_animation() -> void            # 出现动画
func remove_animation() -> void           # 移除动画
```

### 2. ItemData 资源 (`scripts/resources/item_data.gd`)

**职责：**
- 定义物品的静态数据（配置）
- 提供本地化名称和描述
- 定义物品类型和稀有度

**已移除：**
- ❌ `scene: PackedScene` - 不再需要，使用通用 `Item` 节点

**保留：**
- ✅ `icon: Texture2D` - 图标资源
- ✅ `effect_script: Script` - 效果脚本（未来实现）

### 3. ItemPlacer 工具类 (`scripts/global/item_placer.gd`)

**职责：**
- 根据 `ItemData` 创建 `Item` 节点
- 处理物品放置逻辑
- 验证放置规则

**关键方法：**
```gdscript
static func create_item(item_data: ItemData) -> Item
static func place_item_randomly(board: Board, item_data: ItemData) -> bool
static func place_item_at(board: Board, cell: Cell, item_data: ItemData) -> bool
```

---

## 四、使用示例

### 1. 创建物品节点（作为特殊棋子）

```gdscript
# 加载 ItemData 资源
var item_data = load("res://data/item/prism_tower.tres") as ItemData

# 创建物品节点（返回 ChessPiece 类型）
var piece = ItemPlacer.create_item(item_data)

# 放置到单元格（使用统一的 piece 属性）
cell.piece = piece
piece.position = Vector2.ZERO
piece.spawn_animation()
```

### 2. 自动放置到随机位置

```gdscript
# 从升级系统获取选中的 ItemData
var selected_item_data: ItemData = ...

# 自动放置到棋盘随机空位
ItemPlacer.place_item_randomly(board, selected_item_data)
```

### 3. 放置到指定位置

```gdscript
# 放置到指定单元格
var target_cell = board.get_cell(Vector2i(4, 4))
ItemPlacer.place_item_at(board, target_cell, item_data)
```

## 五、优势分析

### 1. 统一处理
- ✅ **单一节点：** 道具和棋子使用同一个 `ChessPiece` 节点
- ✅ **无需区分：** 不需要特殊处理道具，统一使用 `cell.piece`
- ✅ **代码简化：** 减少条件判断和特殊逻辑

### 2. 代码复用
- ✅ **复用动画：** 道具复用所有棋子的动画逻辑
- ✅ **复用交互：** 道具复用所有棋子的交互逻辑
- ✅ **易于维护：** 修改一个节点，所有棋子（包括道具）受益

### 3. 灵活性
- ✅ **策略模式：** 通过 `ItemData` 配置道具外观
- ✅ **易于扩展：** 添加新道具只需创建新的 `ItemData` 资源
- ✅ **动态切换：** 可以在运行时切换显示模式

### 4. 性能优化
- ✅ **场景复用：** 减少场景文件数量
- ✅ **资源优化：** 共享相同的节点结构
- ✅ **内存效率：** 减少重复的节点树

## 六、显示模式对比

### SHAPE 模式（普通棋子）
- **用途：** 游戏中的可移动棋子
- **视觉：** 程序生成的几何形状（圆形、方形等）
- **数据：** `piece_type: int`（0-4）
- **行为：** 移动、消除、选择

### ICON 模式（道具）
- **用途：** 游戏中的道具/建筑
- **视觉：** SVG 图标（通过 `Sprite2D` 显示）
- **数据：** `ItemData` 资源
- **行为：** 放置、效果触发、选择（复用棋子逻辑）

## 七、未来扩展

### 1. 效果系统
- 通过 `effect_script` 实现物品的特殊行为
- 例如：棱镜塔参与消除时得分 x2

### 2. 动画系统
- 可以扩展 `Item` 节点添加更多动画
- 例如：工作动画、激活动画

### 3. 交互系统
- 可以添加点击交互
- 例如：显示物品信息、触发效果

---

## 八、总结

**新设计的优势：**
1. ✅ **简化开发：** 不需要为每个物品创建场景
2. ✅ **易于维护：** 统一的节点结构
3. ✅ **灵活扩展：** 通过 `ItemData` 配置新物品
4. ✅ **符合规范：** 遵循组合优于继承的原则

**设计模式：**
- **策略模式：** `ItemData` 作为策略对象
- **组合模式：** `Item` 节点组合 `ItemData` 和视觉效果
- **工厂模式：** `ItemPlacer` 作为工厂创建物品
