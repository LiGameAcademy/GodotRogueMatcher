## 本片实现

新增`services/run_checkpoint/run_state_snapshot.gd`：冻结当前状态、序列化、独立冷恢复校验、Store主备提交及真实持久确认。没有从开局重放，不读取或嵌入RunRecorder.records，也不要求有历史日志才能加载。

首片支持默认配置的正常经典模式INPUT，包含非空构筑、棋子内建能力、次数/计数、锁定预告及六条随机流。阶段模式、冻结选卡、形状解锁/恢复等暂不支持，明确拒绝；旧前缀槽不会自动转换或覆盖。正式入口仍保留旧实现，只有补齐原产品要求后才切换，不能以原型替代未完成的平台或体验门禁。

快照保存棋盘、定义ID及实例计数、运行修正、分数总量/下一计分ID、进度与消费身份、当前状态计数、随机seed/state和预告。累计计分明细不进入新DTO；过去dispatcher去重集合不跨进程保存，保留next_event_id并创建全新scope，旧事件对象不能进入新dispatcher。INPUT中的根结算必须已完成，未结算roots不被裁掉后假称安全。

`RunSnapshot.capture`和`AbilityEvents.data`增加可选历史开关，默认true，既有回放/采集调用保持行为；新快照和安全检查使用false，连读取/复制旧计分明细与已派发ID集合的工作也跳过。当前必要状态仍可随有效构筑变化，不能称所有局面固定大小。

恢复仅构造未初始化的新Run/Board/随机与实例对象，显式赋值和验证，最后完整投影回比。没有调用initialize、生成棋子、取得技能、重抽候选或执行历史效果。共享定义只读，棋盘/计划/计数/RNG独立。旧命令ID在恢复后拒绝为stale，不恢复旧UI返回对象；场景正式接线仍需按epoch拒绝旧回调。

## CoreSystem实际复用

本片直接使用插件的`source/utils/io_strategies/serialization/json_serialization_strategy.gd`纯值JSON序列化类，紧凑、排序输出；沿既有浮点标签与十进制整数表示作精确往返。没有使用对象恢复、NodePath或saveable分组，也没有启用SaveManager模块/自动存档计时器。

插件通用SaveManager和JSONSaveStrategy还包含节点收集、类型/对象转换与AsyncIO封装，不能直接替代规则快照或Web确认契约。本片保留现有CheckpointStore的临时档/读回/主备/失效身份逻辑及WebFiles的IndexedDB CAS/oncomplete确认。后续按实际缺口继续复用框架能力，不为了“用了模块”增加第二个写入者。

## 完整性与故障

- schema、兼容manifest、尺寸、类型/范围、状态摘要、占格/实体ID、技能定义/等级/能力、进度阈值/消费计数、六流/预告及安全点交叉验证。
- 先做实际序列化往返与冷恢复校验，再进入Store，所有工作随当前DTO而非整局命令前缀进行。
- 已知格式损坏载荷可回上一有效快照；未知schema或兼容性问题不静默回滚。原件保留，后续保存不把已拒绝主档顶成唯一有效备档。
- 写入失败保留原档；终局失效仍优先；已有旧prefix槽返回需要明确迁移，不自动重写。
- 首片1MiB序列化上限是实现防护，不是产品体积/性能验收目标；未冻结正式设备预算。

## 原生证据

新快照专项覆盖真实文件往返、最大种子、A/B可变状态与模板隔离、旧事件scope拒绝、缺历史仍可恢复/字节不变、连续相同命令、逐字段/嵌套null与重哈希坏状态、重复技能实例、写失败、规则层回备/坏原件保留、旧槽拒迁移及终局失效。

正常经典seed23的45次移动样本：源Recorder已有425条记录，新快照约6.9KB；一次原生内核真实文件保存约74ms、加载约48ms，后续5条命令一致。这是单次Windows内核测点，未包含正式菜单和表现，不与旧Web16秒直接作跨平台速度比较，也不是性能通过结论。

最终快照/Store/Recovery三脚本42/42、908断言（14.173秒）；共享规则/前缀回放相关四脚本36/36、790断言；快照及旧场景/所有权/采集恢复四脚本21/21、479断言。首轮测试命名/类型边界及固定状态假设失败记录保留，修正后实际执行数量明确；环境证书存储诊断单列，不隐去或当产品错误。

实际Web探针只允许`127.0.0.1:8919`及完整固定参数，只在空槽运行，拒绝覆盖既有数据。0/45移动两个测点分别实际保存、用新adapter打开数据库加载、检查源状态不变、端点与三条相同后继命令。仅单场助手测试，不算真人样本或正式菜单验收；结果按受测版本另附。
