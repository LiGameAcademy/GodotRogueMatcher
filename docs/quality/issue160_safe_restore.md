# #160：安全点载荷与独立恢复候选

基线 `8e4ebe5f40258fe4fe4c803a2e5f2c15cbd90249`，实际副本为 `execution/o5-restore-independent-v2`，拥有独立 `.git`，不共用工作树登记。当前恢复依赖 RunController、RunSnapshot、RuleReplay、RunRandomStreams 与原核对基线 a9e5ebb 的源码哈希相同。

本片提供无 UI 的安全点保存和独立候选恢复 API；**未接 Board/Game、没有玩家可点的继续入口，不代表完整正式续局或 SV01～SV10 通过**。#160 保持开放。

## 数据与所有权

- `RunCheckpointCodec` 定义 `run-checkpoint-prefix-v1`：稳定 run_id、原主种子、终点序号、安全点种类、完整规则快照/摘要、冻结候选缓存和从 Header 到终点的完整规则前缀。全部64位身份和随机 seed/state 沿既有十进制字符串协议。
- 完整前缀是本版内部重建机制，不读取现有 JSONL 文件或路径，不把任意命令回放结果直接当自动槽。逐记录重建后核对确切终点、六流、候选/目标、阶段、预告、继续位置及身份；完整命令执行自然重建最后命令的幂等缓存和事件去重状态。
- 重建只在独立 Run/内存 Recorder 中执行初始化和历史命令，无外部观察者、文件写入或当前场景接管；历史效果不会向当前局重发。返回的新对象保留无文件 Recorder 以支持后续检查点。它不是直接字段反序列化。
- Session 协调既有 Store。为保留候选权重等 binary64 浮点值，内部载荷以 `JSON.stringify(..., full_precision=true)` 编成字符串 package；Store 仅处理包内字符串，不改变既有容器摘要协议。加载先校验包/schema/内外 run 身份，再解析并完整验证载荷。
- manifest 精确匹配 schema、规则、随机协议、引擎构建/版本、平台、模式、内容/配置摘要和候选版本；主种子及完整六流在载荷中验证。未知协议/配置/缺字段不默认补齐，没有迁移。

## 安全点与失败

INPUT 要求 continuation=idle，无待奖励或 active_offer。REWARDS 要求真实非空冻结组、完整目标图、合法奖励身份和已知继续位置；目标缺失、null、Composite 循环或过深在快照遍历前拒绝。两类点均须健康、未退役、事件开放、无能力 ticket 或暂挂后代/匹配/种植/染色。Resolver 新增的 `has_pending_work()` 只读检查四个暂挂集合，包含无爆炸请求的暂挂匹配。

保存先冻结并重建验证，之后才 begin/stage/commit。失败不报告成功；Store 的主备/事务恢复/失效优先级继续生效。加载只返回完全独立候选及 generation/fallback/recovered_write，不改变当前局。源运行状态、随机、原配置和规则档案不因验证失败而改变。

内存 Recorder 必须持有完整前缀和准确终点；未记录的直接状态改写、结束记录或不完整尾部明确拒绝。JSONL 磁盘失败与保存分开：只要内存前缀仍完整即可验证保存，不把采集错误混作规则失败。

Store 只选结构有效代；容器有效但规则端点错误时本片拒绝，不开放任选旧代回滚。规则级损坏后的自动回备和明确告知仍需后续联合接入，不能将本片当完整 SV05。

## 成本与支持范围

最多4096条记录、15MiB内部载荷；再检查实际转义后的 package 不超过16MiB文件上限减4096字节，为容器留空间。超限不截断前缀、不覆盖旧档。重建默认2秒接受门槛：同步调用完成后检查耗时，不能抢占单次规则调用，不承诺严格2秒内返回。

前缀及账本随局增长，存档体积可能超线性增长；不承诺任意长度局均可存取。触限须报告保存失败并保留上一有效档。后续可依据真实成本改直接状态解码或具有完整基态的压缩，不能删掉前缀起点伪装可恢复。
