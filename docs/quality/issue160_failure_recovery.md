**第一次写入完全失败、没有留下任何文件时，无法凭空保证跨重启失效。** Store 返回失败、当前进程拒绝旧票据，界面提示未能验证结束标记，提供重试、取消或确认风险后退出；直接退出可能在下次启动恢复旧检查点。不是持久成功，不承诺断电/外部删除标记绝无回滚。真实满盘失败路径已测；待继续挑战的胜利不算真实终局，也不能因 OS 退出误写终局标记。该待决状态目前提示玩家取消退出并选择继续/结束，或明确选择保留旧检查点退出，不新增未定义的存档安全点、不替玩家作决定。

结构与当前 manifest 已通过，但主载荷出现明确的已知协议损坏时，Session 才自动尝试同一 run、较旧代的 previous，并完整验证其规则前缀/终点。包括坏 JSON/身份/序列/摘要/端点、明确的初始状态或随机流损坏；未知保存/header/RNG 协议、配置不兼容、不支持运行上下文与成本超限仍直接拒绝，不借回备进行迁移或任意选档。两代均坏时拒绝接管，保留原件。

Store 复核被拒绝的主 record 仍是当前确切 record，拒绝陈旧证明、跨 run 或非更旧备份。加载不改写文件；回备成功后沿既有双语状态明确告知。下一次合法保存把被拒绝主档按字节哈希另存为 corrupt 原件，不旋转它去覆盖已验证 previous；新主提交仍沿原 journal/rollback 协议。原有未知版本、失效标记优先、单 worker/Store 所有权不变。
