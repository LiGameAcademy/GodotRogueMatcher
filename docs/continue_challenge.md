# 挑战完成与继续挑战（#97）

原版8阶段累计目标3450分。完整有效行动收束后达到末阶段目标，且棋盘未满，显示挑战完成。满盘仍优先按棋盘结束。

## 玩家选择

- 通关页说明「已完成全部8个阶段」，增加「继续挑战」。继续保留同一棋盘、累计分、构筑、能力实例、随机流、历史和局ID。
- 先领取末阶段延后的三选一，再进入阶段9。后续目标按冻结配置的末阶段增量追加：当前为每阶段1000分，累计4450、5450……。升压间隔沿用末阶段4，每次最多补5枚；每次达标降压并三选一。
- 超额依然带入，下一阶段仍至少完成一次新的有效行动才检验。不会根据玩家爆分动态增大目标。
- 只有挑战完成且仍有空格、记录未终结时允许继续；经典模式和满盘结束不显示该选项。64位目标无法继续累加时禁止追加。

## 工程与记录

ContinueChallengeCommand通过统一编码、幂等和回放管线提交。StageState只保存继续标志，用冻结末阶段配置计算追加目标，不改共享Resource。

BoardRunFlow承担规则阶段结果的表现驱动与记录收束，Board负责协调自己的子视图；提取这项已有职责后Board保持500行以内。GameManager只释放终局通知锁，不重置分数。

末阶段目标结果和检查点立即写盘；待玩家选择返回开始页、重开、退出，或续玩最终结束时，写唯一Footer。不向已结束记录追加内容。退出时已选择续玩的局标记为abandoned，其历史仍保留初始挑战成功；未选择续玩而结束的局为completed/challenge_completed。

追加阶段在HUD与采集投影中显示真实阶段编号，采集补棋边界按配置读取。规则版本run-commands-v28-continue-challenge；旧记录保留，跨版本精确回放不自动迁移。

## 验收

通关→继续→末阶段三选一→阶段9。确认棋盘/总分/构筑保留、目标4450、升压重新从3开始且最终封顶5；追加阶段达标还有奖励。选择返回开始页应写completed，续玩后主动结束应保留通关历史并写abandoned；同局只有一个Header与一个Footer，整段命令可回放。
